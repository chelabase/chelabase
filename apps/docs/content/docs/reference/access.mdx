Every route is declared once, in `chelabase-routes`, with the credential it takes and an **access level**. The gateway and the services read the same table. The table below is generated from it and checked by a test, so it can't drift.

## Access levels

| Level | Meaning |
|---|---|
| Public | No identity. Health, the API document, sign-in and accept-invite (the code is the credential). |
| Data API key | A data API key, checked by the gateway. |
| Signed in | Any verified identity (`/v1/me`). |
| Instance admin | Self-hosted: an active tenant admin. Platform: a member of the operator organization. |
| Tenant member | Any active member of the caller's tenant. |
| Tenant admin | An active tenant admin. |
| Project *role* | The caller's effective platform role on the project is at least *role* (Viewer, Developer, Admin). A tenant admin is Admin on every project. |
| Branch | The minimum depends on the target branch: one role for an unprotected branch, another for a protected one. For merges the target is the branch merged into. |
| Act as | At least the given platform role, and the Postgres role asked for (`?role=`, or the console's and SQL editor's role) must be in the caller's effective set. The owner needs Admin. Owner-level, `LOGIN` and reserved roles, and chains through them, are Admin-only. |

How a refusal answers:

| Case | Status | Code |
|---|---|---|
| No grant on the project (its existence isn't revealed) | 404 | `not_found` |
| Grant too low, or the role isn't allowed | 403 | `forbidden`, with `error.required` (the level needed, `owner`, or `role:<name>`) |
| A member with no grants anywhere | 403 | `no_access_yet` |
| A sign-up waiting for approval | 403 | `pending_approval` |
| A feature not designed for platform mode | 403 | `not_available_in_platform_mode` |

`GET /v1/me` returns the caller's capabilities: tenant admin, instance admin, and per project the platform role, the Postgres roles they may act as and (`projects[].databases`) the databases a grant override narrows. It answers 200 for a pending sign-up too, with `member.status: "pending"`. Studio only hides what you can't do; the API decides. See [Members and invites](/docs/using/members-and-invites) and [Roles and schema isolation](/docs/using/roles-and-schema-isolation).
