# TE-RT RT1: realtime core + Studio (implementation plan)

**Goal:** Studio members editing a table see each other's row changes (keys only, refetched as their own role) and selected cells live, saves never silently overwrite a concurrent change, and Studio's platform polling is replaced by events. One new service, `services/realtime`, behind one gateway WebSocket route; NATS gets per-service accounts and computes get their own network first (R11).

**Spec:** `docs/superpowers/specs/2026-10-14-realtime-design.md` (approved 2026-10-14; rulings R1–R22 supersede the sections they name). This plan's W-rulings (below) supersede both. Companion files: the wider red-team `docs/superpowers/plans/2026-10-16-realtime-rt1-redteam.md` (findings W1–W35 and the **per-area checklist**, which every brief quotes for its area) and the pre-flight scan `docs/superpowers/plans/2026-10-16-realtime-rt1-preflight.md` (file:line facts). Implementers read the spec sections, W-findings and checklist areas their task names.

**Architecture:**
- `crates/chelabase-nats`: credentials in `NatsConfig`, per-service inbox prefix, and a new `rt` module (subjects, payload types) shared by every publisher and by realtime.
- `infra/compose` + `tools/cli/src/workbench`: NATS config with one account and one user per service (permissions), a `compute` network, Valkey ACL users, the realtime service.
- rust-postgres fork (`chelabase/rust-postgres`): CopyBoth / replication mode, then a pin bump.
- `crates/chelabase-routes` + `services/gateway`: `Service::Realtime`, its endpoints, the `websocket` flag, upgrade refusal elsewhere, ticket-free error logs.
- `crates/chelabase-query` + `services/rest`: the console-only `text_of` form, `COLLATE "C"` comparison, a shared `OWNER_LEVEL_SQL` and a public "console session" helper.
- `services/worker` + `crates/chelabase-neon/src/spec.rs`: the `chelabase_realtime` role, compute settings, platform-event and compute-stopping publishers.
- `services/orchestrator`: internal realtime routes (OIDC-verified, read-only member resolution), access and platform events.
- `services/realtime` (new): tickets, sockets, channels, re-authorization, presence, project events (T7); leases, slots, decoder, merge window, per-role filtering (T8).
- `apps/studio`: realtime client, live rows, presence layer, conflict check, event-driven invalidation (T9).

**Tech:** Rust; axum 0.8.9 with `ws` (latest, 2026-04-14); async-nats 0.50.0 (latest); `redis` 1.7.1 (latest) gains a rustls/aws-lc TLS feature for platform mode; NATS server 2.15 (compose) with subject delete markers; Valkey 9.1.2 ACL. No new Studio dependency (global `WebSocket`). Replication client: our rust-postgres fork's new CopyBoth (P1). **Neon/Postgres forks: no change in RT1** (user, 2026-10-16: U16 and W9's stream callbacks go to fork round 4) → no image build; the live pass runs on the pinned images (`629166ceef60-dev`). The rust-postgres fork does change (T2), which is a crate pin, not an image.

**Standing rule (task pipeline):** per task, in sequence: a **test agent** writes and commits the RED tests from the brief and its checklist (`tN: RED tests`), compiles every target (live ones `--no-run`), runs each runnable one against the base and shows it failing on its first assertion for the intended reason; a **coder agent** makes them GREEN without editing, weakening, skipping or deleting them; an **audit agent** (the task's reviewer) reviews and tidies, checks `git diff <red-commit>..HEAD` on the RED files is empty, and reports defects and hardening separately. No agent spawns agents. At most 3 agents at once, at most 2 pipelines in parallel.
