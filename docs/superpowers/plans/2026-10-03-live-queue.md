    - `just live -- deps-up` (or any recipe) is how shared-infra changes (new image pins) run, so nobody changes the stack under someone else's test.
    - Plain `just dev`, `deps-up`, `deps-down`, `sweep-dbs` and the e2e/live recipes refuse to run while another worktree holds the lock (they print the holder); inside `just live` they run normally.

## Task 2: `scripts/live.sh`

Interface pinned in "Models and schedule". Pure bash + `flock`; state under `${CHELADB_LIVE_DIR:-$main/.cheladb/live}` (tests point it at a temp dir). `run` takes a ticket (`<epoch-ns>-<pid>`), waits (poll 1 s) until its ticket is the oldest live one and the lock is free, holds `flock -n` on the lock fd for the command's lifetime, writes the holder file, and calls a `LIVE_SWAP_DEV` hook (the recipe passes the dev-swap commands; tests stub it). Dead tickets/holders (pid gone) are cleared by any waiter.

**Tests (`scripts/tests/live.sh`, run by `just live-test`):** `two_runs_queue_in_order`; `a_crashed_holder_is_cleared`; `ctrl_c_releases`; `status_shows_holder_and_queue`; `check_exits_3_for_another_worktree`; `same_worktree_skips_the_dev_swap`.
