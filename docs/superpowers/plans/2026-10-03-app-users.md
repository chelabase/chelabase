# Projects and app users: Implementation Plan (roadmap step 6b)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Strict TDD (a RED run before code; a compile error counts only when the missing item is the code under test). Work only in your task's worktree (`.worktrees/app-users-tN`), with absolute paths, `git -C <wt>` and `just --justfile <wt>/justfile --working-directory <wt>`. Read `CLAUDE.md`. Implementers commit on their task branch; they don't push, merge or run the stack.

**Goal:** projects become a real resource (create, list, rename, cascading delete), and each project can switch on app users: a Zitadel org per project, an app-owned users table guarded in the app's database, Cheladb-issued EdDSA access tokens with rotating refresh tokens, `db.auth` in the SDK, three-way sync, and user admin in Studio.

**Architecture:**
- **Metadata** gets project lifecycle columns, `project_auth`, `branch_auth_sync` and `app_sessions`.
- **Orchestrator:**
  - public routes for projects, app-user settings and user admin;
  - internal routes (new `app-auth` bearer) for branch info, sessions and sync;
  - the Zitadel Actions webhook.
- **Worker:**
  - jobs `project_delete`, `app_users` (enable/disable/reconcile) and `app_users_sync`;
  - the users bootstrap on branch create and switch;
  - the claim helpers in the data API bootstrap.
- **`auth`** owns the `/auth/v1/app/*` flows. It connects to the compute as `cheladb_auth_sync` for the sign-up transaction, and signs access JWTs.
- **Gateway** verifies `Cheladb-User` on data-key routes, and puts the claims in the internal identity.
- **New crate `crates/cheladb-zitadel`:** the v2 client, an axum mock, and Actions signature verification.

**Tech stack:** Rust 2024, axum 0.8.9, sqlx 0.9.0, moka 0.12.16, utoipa 6.0.0, jsonwebtoken 11.1.0 (aws_lc_rs), async-nats 0.50.0, React 19 + TanStack Router/Query, orval, vitest.
- **No new third-party dependencies.** Already in `[workspace.dependencies]`: `hmac` 0.13.0, `sha2` 0.11.0, `subtle` 2.6.1, `hex`, `base64` 0.23.1, `async-trait` 0.1.92, `ed25519-dalek` 3.0.0.
- The only new crate is our own `cheladb-zitadel`. A task that wants a dependency not in the workspace list must ask first.

**Spec:** `docs/superpowers/specs/2026-10-03-app-users-design.md`. The spec wins on behaviour; this plan wins on names, interfaces and the P-rulings below.

  - **P6. Protection objects:**
    - Two event triggers, `cheladb_users_protect_drop` (sql_drop) and `cheladb_users_protect_ddl` (ddl_command_end, tags `ALTER TABLE`, `ALTER INDEX`, `ALTER SCHEMA`, `ALTER TRIGGER`, `CREATE TRIGGER`). Postgres binds an event trigger to one event, so the spec's one trigger becomes two.
    - The ddl checks run only when the command touches the users table (its oid, kept in `cheladb.app_users_table.table_oid`), its schema, or one of its triggers. They are then state-based: the table by name, each managed column and its type, and both guard triggers enabled. Unrelated DDL is never blocked, even when the users table is in a broken state (pre-flight C2).
    - Both bootstraps (users and teardown) drop the protect triggers right after taking the advisory lock, so a broken state can't block them.
    - The row guard is an `AFTER` trigger, so an owner's `BEFORE` trigger sorting later can't rewrite `NEW` after the check (I2).
    - A second guard trigger, `cheladb_users_guard_truncate` (BEFORE TRUNCATE), closes the TRUNCATE hole the spec missed.
    - *Cost: none.*

    - *Cost: none.*
  - **P10. Refresh tokens:**
    - Reuse means presenting the **previous** token outside the grace window: the session is revoked and the answer is 401 `refresh_token_reused`.
    - An unknown secret for a live session answers 401 `refresh_token_invalid` and doesn't revoke. Only one generation back is detectable, and this way an access-token holder can't kill a session with garbage.
    - Within the grace window, the previous token gets the same new refresh token back, with a freshly minted access JWT.
    - A token whose session belongs to another project answers `refresh_token_invalid`.
    - *Cost: a token two rotations old is not flagged as reuse.*
  - **P11. Password changes and sessions:**
    - `change-password` answers 200 with a fresh session (sign-in shape) instead of 204.
    - The webhook's `user.human.password.changed` revokes the user's sessions **created before the event's `created_at`**, so the fresh session survives while every older one dies.
    - `password-reset-confirm` revokes all sessions (204).
    - *Cost: the SDK swaps in the new tokens.*
  - **P12. Taken email at sign-up:**
    - Verification off (the self-hosted default): 409 `email_taken`, as the platform's skip mode does.
    - Verification on: the decoy `{user, verification_required: true}`, padded, plus the reset-email notice.
    - A `23505` on the email index counts as taken.
    - *Cost: with verification off, sign-up reveals that an email exists (it would hand out tokens otherwise).*

## Global Constraints

- Never mirror Supabase. Names are ours: `db.auth`, `Cheladb-User`, `cheladb.user_id()`.
- Errors use `cheladb_types::api_error::{ApiError, ErrorCode}` with the envelope `{"error":{"code","message"}}`. Invalid input is 422 `invalid_request`. The new codes are listed in T2.
- Self-hosted defaults: `email_verification = false`, `on_delete = delete`.
- Every new platform route goes in `crates/cheladb-routes` (`ENDPOINTS`) and the orchestrator's utoipa routes. Also update `operation_ids_are_the_contract`, `schema_names_are_api_facing` and the tag list in `every_response_has_a_description_and_errors_use_the_envelope` (`openapi.rs`).
  - Orchestrator entries go after `orchestrator::DELETE_ROLE`; auth entries go after `auth::LOGOUT`. Keeping to these places avoids merge conflicts.
- Every new port method gets its `Doc` stub (`openapi.rs`) and test fakes (`tests/api.rs` `FakeMetadata`/`FakeJobs`, `tests/internal.rs` `FakeNeon`, worker `fakes.rs` `FakeMetadata`).
- Never run `cargo fmt` on the workspace; rustfmt only files you create. Never edit an applied migration. Never overwrite `.cheladb` keys.
- **SQL style** (as `data_api.rs`):
  - top-level statements are `pg_catalog`-qualified, with `OPERATOR(pg_catalog.=)`;
  - functions with `SET search_path = pg_catalog, pg_temp` use plain operators inside;
  - one transaction under `pg_advisory_xact_lock(BOOTSTRAP_LOCK_KEY)` (the data API's key, so the two bootstraps serialise).
- Live tests and e2e run only through `just live …`, one at a time. Implementer worktrees never run the stack.
- Commits: `git commit`, ending with the `Co-Authored-By` and `Claude-Session` trailers.

## Review Focus

1. **Refresh rotation:**
   - the previous token inside 10 s returns the *same* new refresh token;
   - outside 10 s it revokes the session (401 `refresh_token_reused`, and the Zitadel session is deleted);
   - an unknown secret doesn't revoke.

   Tests: T1 `refresh_rotates_grace_and_reuse` (SQL) and T7 `refresh_grace_returns_the_same_token`, `refresh_reuse_revokes_and_deletes_the_zitadel_session`.
2. **The gateway never falls back to `anon`:** with a public key, an invalid, expired or revoked `Cheladb-User` gets 401 with its code and is never proxied; a secret key with the header gets 400. Test: T10 `user_token_never_falls_back_to_anon`.
3. **The guard holds on a real compute:**
   - the owner can't insert, delete, truncate or change managed columns;
   - the owner can update app columns;
   - the sync role can do all of it;
   - dropping or renaming the table, a managed column or the trigger, and disabling the trigger, are refused.

   Tests: T15 `guard_refuses_the_owner_and_allows_sync` and `protect_refuses_drop_rename_retype_disable` (and T4's pinned SQL).
4. **Sign-up atomicity:** a constraint failure never calls Zitadel; a commit failure deletes the Zitadel user; an unknown `data` column is 422 before Zitadel. Tests: T9 `constraint_failure_never_calls_zitadel`, `commit_failure_deletes_the_zitadel_user`, `unknown_column_is_422_before_zitadel`.
5. **Webhook trust:** a wrong or old signature gets 401; another org's event is ignored with 200; a fixed vector verifies. Tests: T3 `signature_matches_the_fixed_vector`, `old_timestamp_is_refused`, and T7 `webhook_rejects_bad_signature_and_ignores_other_orgs`.

**Behaviour rules:**
- **`create_project`:** compute `slug_base`, then insert with the first free slug among `base`, `base-2`, `base-3`, …. Truncate the base so the slug stays ≤ 40 characters. Retry on a unique violation of `projects_live_slug` (at most 20 tries, then `Conflict`).
- **`begin_project_delete`** runs in one transaction, locking the project row and then its databases rows (`FOR NO KEY UPDATE`, the branches.rs lock order):
  - refuse in this order: missing or other tenant → `NotFound`; `deleting` → `AlreadyDeleting`; a database `pending`/`provisioning` → `NotReady(id)`; any live branch `protected` → `Protected(id)`; `project_auth.status` `enabling`/`disabling` → `AppUsersBusy`;
  - otherwise set the project to `deleting` and every database in `ready`/`failed` to `deleting`, and return those ids. Databases already `deleting` aren't returned; reconcile retries them.
- **`finish_project_delete`** runs in one transaction: revoke the project's sessions, delete `branch_auth_sync` rows of the project's branches, delete `project_auth`, and set the project to `deleted`, `deleted_at = now()`, `error = NULL`.
- **`begin_enable_app_users`** locks the project row (`FOR UPDATE`) and returns `MetadataError::ProjectDeleting` unless the project is `active`. Then:
  - no row → insert `enabling` → `Started`;
  - a `failed` row with the same `database_id`/`pg_database`/`schema_name`/`table_name` → set `enabling`, clear `error`, update the two settings → `Retry`;
  - any other row → `Exists(row)`.
- **`finish_enable_app_users`** moves a row only from `enabling`, to `enabled` or to `failed` with the error.
- **`begin_disable_app_users`** moves `enabled` or `failed` to `disabling`.
- **`refresh_app_session`** (pinned; one transaction):
  ```sql
  SELECT id, project_id, user_id, zitadel_session_id, refresh_hash, prev_refresh_hash, grace_refresh_sealed,
         grace_until, created_at, last_used_at, expires_at, revoked_at, now() AS now
    FROM app_sessions WHERE id = $1 FOR UPDATE;
  ```
  - No row, `project_id ≠ project`, or `revoked_at IS NOT NULL` → `Invalid`, with no write (I5).
  - `now >= expires_at` or `now >= created_at + cap` → `UPDATE … SET revoked_at = now()`, then `Invalid`.
  - `presented = refresh_hash` → rotate:
    ```sql
    UPDATE app_sessions SET prev_refresh_hash = refresh_hash, refresh_hash = $2,
           grace_refresh_sealed = $3, grace_until = now() + $4::interval, last_used_at = now(),
           expires_at = LEAST(now() + $5::interval, created_at + $6::interval)
     WHERE id = $1 RETURNING …;
    ```
    Returns `Rotated`.
  - `presented = prev_refresh_hash` and `grace_until > now` → `Grace { sealed: grace_refresh_sealed }`, with no change.
  - `presented = prev_refresh_hash` (grace over) → set `revoked_at = now()` → `Reused(session)`.
  - Anything else → `Invalid`, with no change (P10).
- **`revoke_user_sessions`** revokes live sessions of `(project, user)` except `keep`, limited to `created_at < created_before` when that is given, and returns the revoked ones.
- **`purge_app_sessions`** deletes rows revoked or expired more than `older_than` ago.

```rust
pub fn verify_signature(header: &str, body: &[u8], signing_key: &str, now_unix: i64) -> Result<(), SignatureError> {
    let (mut t, mut sigs) = (None, Vec::new());
    for part in header.split(',') {
        let (k, v) = part.trim().split_once('=').ok_or(SignatureError::Malformed)?;
        match k {
            "t" => t = Some(v.parse::<i64>().map_err(|_| SignatureError::Malformed)?),
            "v1" => sigs.push(v),
            _ => {}
        }
    }
    let t = t.ok_or(SignatureError::Malformed)?;
    if sigs.is_empty() { return Err(SignatureError::Malformed); }
    if now_unix - t > TOLERANCE_SECS { return Err(SignatureError::Expired); }   // Zitadel only refuses old ones
    let mut mac = <Hmac<Sha256> as KeyInit>::new_from_slice(signing_key.as_bytes()).expect("any key length");
    mac.update(t.to_string().as_bytes());
    mac.update(b".");
    mac.update(body);
    let expected = mac.finalize().into_bytes();
    for s in sigs {
        if let Ok(raw) = hex::decode(s)
            && raw.len() == expected.len()
            && bool::from(raw.as_slice().ct_eq(expected.as_slice()))
        {
            return Ok(());
        }
    }
    Err(SignatureError::Mismatch)
}
```

```sql
CREATE OR REPLACE FUNCTION cheladb.users_protect() RETURNS event_trigger
  LANGUAGE plpgsql SECURITY DEFINER SET search_path = pg_catalog, pg_temp AS
$f$
DECLARE
  cfg record;
  obj record;
  rel oid;
  found_type text;
  managed text[] := ARRAY['id', 'email', 'email_verified', 'created_at', 'deleted_at'];
  types text[] := ARRAY['uuid', 'text', 'boolean', 'timestamp with time zone', 'timestamp with time zone'];
BEGIN
  IF to_regclass('cheladb.app_users_table') IS NULL THEN RETURN; END IF;
  SELECT schema_name, table_name, table_oid INTO cfg FROM cheladb.app_users_table;
  IF NOT FOUND THEN RETURN; END IF;
  rel := cfg.table_oid;
  IF TG_EVENT = 'sql_drop' THEN
    FOR obj IN SELECT * FROM pg_event_trigger_dropped_objects() LOOP
      IF obj.classid = 'pg_class'::regclass AND obj.objid = rel AND obj.objsubid = 0 THEN
        RAISE EXCEPTION USING ERRCODE = '42501', MESSAGE =
          format('table %I.%I is managed by Cheladb app users: disable app users first', cfg.schema_name, cfg.table_name);
      END IF;
      IF obj.object_type = 'table column' AND obj.objid = rel AND obj.address_names[3] = ANY (managed) THEN
        RAISE EXCEPTION USING ERRCODE = '42501', MESSAGE =
          format('column %I of %I.%I is managed by Cheladb app users', obj.address_names[3], cfg.schema_name, cfg.table_name);
      END IF;
      IF obj.object_type = 'trigger'
         AND obj.address_names[1] = cfg.schema_name AND obj.address_names[2] = cfg.table_name
         AND obj.address_names[3] IN ('cheladb_users_guard', 'cheladb_users_guard_truncate') THEN
        RAISE EXCEPTION USING ERRCODE = '42501', MESSAGE =
          format('trigger %I of %I.%I is managed by Cheladb app users', obj.address_names[3], cfg.schema_name, cfg.table_name);
      END IF;
    END LOOP;
    RETURN;
  END IF;
  -- ddl_command_end: only commands that touch the users table, its schema or its triggers are checked,
  -- so unrelated DDL works whatever state the users table is in.
  IF NOT EXISTS (SELECT FROM pg_event_trigger_ddl_commands() c
                  WHERE (c.classid = 'pg_class'::regclass AND c.objid = rel)
                     OR (c.classid = 'pg_namespace'::regclass
                         AND c.objid = (SELECT k.relnamespace FROM pg_class k WHERE k.oid = rel))
                     OR (c.classid = 'pg_trigger'::regclass

    RETURN;
  END IF;

    RAISE EXCEPTION USING ERRCODE = '42501', MESSAGE =
      format('table %I.%I is managed by Cheladb app users: it can''t be renamed or moved', cfg.schema_name, cfg.table_name);
  END IF;
  FOR i IN 1 .. array_length(managed, 1) LOOP
    found_type := NULL;
    SELECT format_type(a.atttypid, a.atttypmod) INTO found_type FROM pg_attribute a
     WHERE a.attrelid = rel AND a.attname = managed[i] AND NOT a.attisdropped;
    IF found_type IS DISTINCT FROM types[i] THEN
      RAISE EXCEPTION USING ERRCODE = '42501', MESSAGE =
        format('column %I of %I.%I is managed by Cheladb app users: it can''t be renamed, dropped or retyped', managed[i], cfg.schema_name, cfg.table_name);
    END IF;
  END LOOP;
  IF (SELECT count(*) FROM pg_trigger t
       WHERE t.tgrelid = rel AND t.tgname IN ('cheladb_users_guard', 'cheladb_users_guard_truncate')
         AND t.tgfoid = 'cheladb.users_guard()'::regprocedure AND t.tgenabled IN ('O', 'A')) <> 2 THEN

      format('the cheladb_users_guard triggers on %I.%I are managed by Cheladb app users: they can''t be disabled, renamed or replaced', cfg.schema_name, cfg.table_name);
  END IF;
END
$f$;
```

- **change-password `{current_password, password}`:** needs a user; `change_password`; a wrong current password → 401 `invalid_credentials`.
