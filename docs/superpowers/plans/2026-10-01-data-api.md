# Data API Engine: Implementation Plan (roadmap step 6)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** apps read and write a branch's tables over `POST /data/v1/query` with per-branch keys and a typed TypeScript SDK.

**Architecture:**
- The gateway resolves a key to a branch and role through the orchestrator's internal listener, then mints the internal identity token.
- A new service, `cheladb-rest`, trusts only that token. It connects directly to the branch's compute as `authenticator` and runs one generated statement per operation inside a transaction that sets the role and claims. The SQL depends only on the query's shape; values are always bind parameters.
- The worker installs the `cheladb` machinery schema and `authenticator`'s login on every compute (re)creation.

**Tech stack:** Rust 2024 (axum 0.8.9, sqlx 0.9.0, tokio, moka 0.12.16, Pingora 0.9.0), NATS, Postgres 17 on Neon, TypeScript (vitest), React Studio.

**Spec:** `docs/superpowers/specs/2026-10-01-data-api-design.md`. Executors read both the spec and this plan; the spec wins on behavior, and this plan wins on names and interfaces.

## Review Focus

1. **Hostile names and values.** A table or column named with quotes, semicolons, mixed case (`"Order"`), reserved words (`user`, `select`) or Unicode lookalikes either resolves exactly to the real object and is quoted correctly, or gets `unknown_*`. A value is never part of the SQL text. Tested in Task 5 (golden tests with such names) and Task 6 live (a table named `"Order"` with a column `select`).
2. **A schema rewound by a restore or a branch at a past point**, and a compute that moved after reset or restore. The engine serves the schema that's really there (the version uuid matches) and reconnects once. Tested live in Task 6.
3. **A revoked key, and a flood of random keys.** A revoked key stops working within 30 s. Random keys get 401, and past 20 misses a second they get 429, without one lookup per request reaching the internal listener. Tested in Task 4.
4. **A database whose user has damaged the machinery.** `cheladb` dropped, the event trigger disabled, `authenticator`'s password changed, or grants revoked: requests answer `unavailable` until reconcile's bootstrap heals it, and the bootstrap is idempotent on a healthy database. Tested in Task 2 (fakes, plus the exact SQL) and Task 6 live.
5. **Edge payloads.**
   - a body just over 1 MiB → 413;
   - a batch of 50 where the last operation fails → everything rolled back;
   - `numeric` with 30 digits round-trips exactly as a string;
   - insert rows with different key sets → `invalid_query`;
   - `limit` above `max_rows` → clamped;
   - `in: []` → no rows, not an error.

   Tested in Task 5 (parser and generator) and Task 6 live.

```sql
    id            uuid PRIMARY KEY,
    branch_id     uuid NOT NULL REFERENCES branches (id) ON DELETE CASCADE,
    kind          text NOT NULL CHECK (kind IN ('public', 'secret')),
    role          text NOT NULL CHECK (length(role) BETWEEN 1 AND 63),
    name          text NOT NULL CHECK (length(name) BETWEEN 1 AND 63),
    prefix        text NOT NULL,
    sha256        bytea NOT NULL UNIQUE CHECK (length(sha256) = 32),
    sealed        text,
    created_at    timestamptz NOT NULL DEFAULT now(),

CREATE INDEX data_api_keys_branch ON data_api_keys (branch_id);
CREATE UNIQUE INDEX data_api_keys_one_live_public ON data_api_keys (branch_id)

ALTER TABLE databases
```

```rust
                                                               // batch ≤ 50 and no nesting, limit ≥ 0, offset ≥ 0
pub struct Name { pub schema: Option<String>, pub name: String }   // "t" | "s.t"; at most one dot; nonempty parts
// Values stay serde_json::Value until binding.

// sql.rs: needs a resolved view of the schema; the trait keeps this task free of introspection
pub trait Catalog {
    fn table(&self, name: &Name) -> Option<&TableInfo>;          // None = unknown or not visible to the role
    fn function(&self, name: &Name, arg_names: &[&str]) -> Result<&FunctionInfo, FnLookupError>; // NotFound | Ambiguous
}
pub struct TableInfo { pub schema: String, pub name: String, pub columns: Vec<ColumnInfo> }
pub struct ColumnInfo { pub name: String, pub type_sql: String /* format_type output, e.g. "numeric(10,2)", "public.mood" */,
                        pub array: bool, pub text_like: bool, pub generated: bool }
pub struct FunctionInfo { pub schema: String, pub name: String, pub args: Vec<(String, String /* type_sql */)>,
                          pub returns_set: bool }
pub struct Plan { pub sql: String, pub binds: Vec<Bind> }        // one statement per operation; a batch → Vec<Plan>
pub enum Bind { Text(Path), Json(Path) }                         // Path addresses the value in the tree; the executor binds text or jsonb
pub fn plan(op: &Op, catalog: &impl Catalog, max_rows: i64, default_schema: &str) -> Result<Vec<Plan>, PlanError>;
    // PlanError → unknown_table | unknown_column | unknown_function | invalid_query (e.g. like on a non-text column)

// shape.rs
pub fn shape_hash(op: &Op) -> u64;   // std::hash::DefaultHasher::new() (stable within one process, which is all the cache needs);
                                    // hashes structure and names, never values, row counts or `in` lengths
```

**SQL rules:** exactly the spec's "SQL generation" section.
- **Identifiers** are always quoted (a `"` inside is doubled) and come only from the catalog's spelling, never from the request.
- **Text binds:** `CAST($n AS <type_sql>)`.
- **Inserts and `set`:** `jsonb_populate_recordset` / `jsonb_populate_record` with `NULL::"s"."t"`.
- **`in`:** `= ANY (SELECT CAST(x AS <type_sql>) FROM jsonb_array_elements_text($n) x)`. `in: []` yields no rows naturally.
- **`is`:** `IS NULL`, `IS TRUE` or `IS FALSE`, with no bind.
- **Limits:** `limit` becomes `min(limit, max_rows)` and is sent as a bound parameter (`LIMIT $n`). Without `limit`, `max_rows` applies, and `returning` is capped the same way.
- **`orderBy`:** `nulls` is `first` or `last`; `dir` is `asc` or `desc`.
- **Writing to a generated column** gives `invalid_query`.
- **Function calls** use named notation (`"a" => CAST($1 AS t)`) and resolve to exactly one function by schema, name and argument-name set (args with defaults may be omitted).

Each has `max_connections = settings.max_connections`, `min_connections = 0` and `idle_timeout = 60 s`, and an idle pool is dropped after 5 min (a moka `time_to_idle`). A global `tokio::sync::Semaphore` of `CHELADB_REST_MAX_CONNECTIONS` permits is held for the life of each acquired connection.
- **Transaction**, in this order:
  1. `BEGIN`.
  2. One round trip:
     ```sql
     SELECT set_config('role', $1, true), set_config('request.jwt.claims', $2, true),
            set_config('statement_timeout', $3, true), (SELECT version::text FROM cheladb.schema_version)
     ```
     If `cheladb.schema_version` is missing (42P01), answer 503 `unavailable` with the spec's message.
  3. If (branch, version) isn't cached, introspect in the same transaction. The system catalogs are readable by every role, and visibility uses `has_*_privilege(<role>, …)` with the role named explicitly, so running under the switched role is fine.
  4. Plan through the shape cache (`(branch, version, role, default_schema, shape_hash)` → `Vec<Plan>`; amended after Task 5's review), then bind each plan's values with `resolve_bind(op, &bind, max_rows)`.
  5. Bind and run each plan with `query_scalar::<_, String>`.
  6. `COMMIT`.

  A batch returns `[r1,r2,…]` by joining the strings. The response is `200`, `content-type: application/json`, with the bytes as-is.
- **Introspection:** one or two catalog queries covering tables, views, matviews, columns (`format_type`), enums, domains (mapped to their base type, but `type_sql` keeps the domain name for the cast) and functions in non-reserved schemas, plus `relrowsecurity`.
- **Visibility:** per (branch, version, role), computed with one query using `has_schema_privilege`, `has_table_privilege` (any of select, insert, update, delete), `has_any_column_privilege` and `has_function_privilege`, then cached.
- **Moved compute:** a connect error (sqlx `Io` or `Tls` while acquiring) drops the branch's connection info and pool, refetches, and retries once. Errors after a statement was sent are never retried.
- **Errors:** SQLSTATE maps to the spec's table in `error.rs`. 500s log the detail with the request id and return a generic message.
- **Body cap:** 1 MiB (`DefaultBodyLimit`) gives 413 `too_large`.
