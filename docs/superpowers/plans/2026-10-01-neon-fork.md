## Task 3a: Dependency security bumps (in `ChelaDB/neon`, PR `deps/advisories`)

**Why:** Neon's frozen `Cargo.lock` carries RustSec advisories published since upstream froze. Task 3 found them: vulnerabilities in `h2` (unbounded empty DATA frames), `bytes` (`BytesMut::reserve` overflow), `quick-xml` (quadratic duplicate-attribute check, `NsReader` memory exhaustion), `crossbeam` (`fmt::Pointer` on `Atomic`/`Shared`) and `diesel` (COPY command injection, SQLite/MySQL unsoundness); unsoundness in `anyhow` (`downcast_mut`); unmaintained `bincode` and `adler`. Task 3 left `cargo deny check advisories` report-only so the baseline stays unchanged code (decided by the user 2026-10-01).

**Behavior:**
1. List every advisory with `cargo deny check advisories` (as CI runs it) and record the full list in the PR body.
2. Fix with the smallest change first:
   - `cargo update -p <crate> --precise <first fixed version>` within semver;
   - larger bumps (a new major, or Cargo.toml edits) only where no compatible fix exists, keeping code changes minimal and listed per crate;
   - "Latest versions first" applies: check crates.io for the fixed release, and prefer the newest compatible release.
3. What can't be fixed now (for example `bincode` unmaintained with no drop-in, or an advisory in a crate only test code uses) goes into `deny.toml` `[advisories] ignore = [{ id = "RUSTSEC-…", reason = "…" }]`, each with a concrete reason. Like `known_failures.txt`, that list may only shrink.
4. Make `cargo deny check` blocking again in `pr.yml`'s `lint`, for advisories, bans, licenses and sources.

**Tests:** the gate is `ci-ok` green, with **no change to `known_failures.txt`**. A test that newly fails is a regression from a bump: fix it or back that bump out. RED for this task is `cargo deny check advisories` failing (blocking) on the base commit; GREEN is the PR's run.

**Report:** every advisory with its outcome (bumped from → to, Cargo.toml change, or ignored with reason) and any code edits.
