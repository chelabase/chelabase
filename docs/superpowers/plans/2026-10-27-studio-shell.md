**Goal:** At phone width the left rail becomes a menu button in the header that opens it as an overlay drawer; every Studio page gets a header breadcrumb; the project Branches page and project forms stop hiding overflowing content (KI-1); the invite form's role chips stop spilling (KI-2).

**Spec:** none. The scope is the roadmap's "Follow-up recorded (user, 2026-10-24): a Studio shell step" plus the coordinator's rulings below. Design reference: `docs/superpowers/designs/2026-10-23-members-hub/` (`comp.css` `.topbar`, `.crumbs`, `.menu-btn`; header markup in `04-member-admin-view.html`; PNGs in `png/` at 390 and 1440).

**Architecture:** All in `apps/studio/src`. **Tech:** TypeScript, React, TanStack Router, Base UI, Tailwind, vitest + Testing Library. No new dependency. No fork change: no image build; the browser pass runs on the pinned images.

T1 tests a role named `a/b%c é` end to end (real memory router, label registered with the router's param, crumb shows it). ## Shared interfaces (pinned)

(Revised by the seam pass, S1-S3, S9, S10, S13, S14.)

In `apps/studio/src/lib/crumbs.ts` (pure, no React):
- `export interface Crumb { key: string; label: string; to?: string; params?: Record<string, string>; search?: Record<string, unknown>; loading?: boolean }`. The last crumb has no `to`. `loading: true` renders "…" and no link (P6). `to` is a route template (`"/app/projects/$projectId"`, `TABLES_ROUTE`), never a path with values spliced in; values go in `params`, so the router encodes them once.
- `export type CrumbLabel = { id: string; label: string }` and `export type CrumbLabels = Readonly<Record<string, CrumbLabel>>`, keyed by the dynamic param name: `projectId`, `databaseId`, `memberId`, `role`, `table` (no others; `mergeId` and `branchId` never get labels, S3). A label applies only when its `id` equals the current param value (S1).
- `export type CrumbParams = Readonly<Record<string, string | undefined>>`: the router's decoded params of the deepest match.
- `export function buildCrumbs(pathname: string, params: CrumbParams, labels: CrumbLabels): Crumb[]`. The pathname picks the shape (`/app` or `/app/`, `/app/projects/…`, `/app/tables…`, `/app/api`, `/app/members…`); every dynamic value comes from `params`, never from decoding the pathname (S2). `/app` gives `[Projects]`; `/app/projects/:projectId` gives `Projects › <project>`; `/app/projects/:projectId/databases/:databaseId/merges/:mergeId` gives `Projects › <project> › <database> › Merge` (the database crumb is text, not a link: S4; "Merge" is a static label); `/app/tables/...` gives `Tables › <table>` when `params.table` is set, else `Tables` (Q1, S6); `/app/api` gives `API`; `/app/members` gives `Members`; `/app/members/:memberId` gives `Members › <name>`; `/app/members/roles/:databaseId/:branchId/:role` (recognised by `params.role` being set) gives `Members › Roles › <role>` with the Roles crumb of S5.
