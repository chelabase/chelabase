# Repo Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the repo a conventional layout before step 3: Studio is the only app, backends live under `services/`, and the CLI under `tools/`. Rename `ui-auth` to `auth`, and the misnamed `cheladb auth …` commands to `cheladb dev …`.

**Architecture:**
- The folder moves (`git mv`) leave every package name as it is, except `ui-auth`, which becomes `auth`.
- Cargo, moon and docs follow the new paths.
- No behaviour changes: the full test suite and the live checks must pass before and after.

**Tech Stack:** Cargo workspace, pnpm workspace, moon, just, Compose.

**Spec:** none. The layout was agreed in conversation on 2026-09-28:

```
apps/studio          the only user-facing app
services/            gateway, orchestrator, worker, auth (was ui-auth); later rest
tools/cli            the `cheladb` binary (binary and package name unchanged)
crates/, packages/   shared Rust and TypeScript libraries, unchanged
```

- **Branch:** `repo-layout`, off `main`. Merge only when the user says. Push only when asked.

- **History:** move with `git mv`, one commit for the moves alone, so `git log --follow` keeps each file's history.
- **Never:** run `cargo fmt` across the workspace, run `just sweep-dbs`, or overwrite `.cheladb/secrets/secrets.key`, the gateway key pair or the cookie key. The cookie key is **moved**, not regenerated (Task 2).
- **Old plans and specs** under `docs/superpowers/` are historical records: don't rewrite their paths. Update only `README.md`, the roadmap and the files this plan names.
- **Env var rename:** `CHELADB_UI_AUTH_*` becomes `CHELADB_AUTH_*`, with no fallback to the old names. `demo.env` is regenerated by every `just dev`, and nothing else sets them. The prefix is unused today (checked).
- **Ports don't change:** auth stays on 8084.
- **WSL:** if tests fail binding `127.0.0.1:0`, wait a minute and rerun; ephemeral ports are exhausted.

## Review Focus

1. **An existing `.cheladb/ui-auth/cookie.key` must survive the rename.** Bootstrap moves the folder to `.cheladb/auth/` once. It must never generate a new key while the old one exists, because that would sign everyone out and break the never-overwrite rule. Test in Task 2.
2. **Both `.cheladb/ui-auth/` and `.cheladb/auth/` exist** (for example after a checkout of an older branch). Bootstrap keeps `auth/`, leaves `ui-auth/` alone and warns, and never merges or overwrites. Test in Task 2.
3. **A stale `demo.env` on another computer** still has `CHELADB_UI_AUTH_*`. The next `just dev` rewrites it before starting services, and auth's error for a missing variable names `just zitadel-bootstrap`. Check in Task 4.
4. **`just cleanup` must still stop a stray auth process.** Its process-name match changes from `ui-auth` to `auth`. Check in Task 4.
5. **Moon still finds every project** after the globs change: `moon query projects` lists the same projects at their new paths. Check in Task 1.

- [ ] **Step 2: Implement the move**

```rust
pub fn migrate_auth_dir(root: &std::path::Path) -> std::io::Result<PathBuf> {
    let old = root.join(".cheladb/ui-auth");
    let new = root.join(".cheladb/auth");
    match (old.exists(), new.exists()) {
        (true, false) => {
            std::fs::rename(&old, &new)?;
            tracing::info!("moved {} to {}", old.display(), new.display());
        }
        (true, true) => tracing::warn!(
            "both {} and {} exist; using the second. Delete the first once you've checked it.",
            old.display(),
            new.display()
        ),
        _ => {}
    }
    Ok(new)
}
```
